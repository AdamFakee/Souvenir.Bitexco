# ĐỀ XUẤT CẢI TIẾN API AUTHENTICATION CHO PHÂN HỆ MOBILE POS

**Ngày đề xuất:** 22/05/2026  
**Mục tiêu:** Chuyển dịch cơ chế quản lý Token từ Cookie (Browser-based) sang truyền nhận trực tiếp qua JSON Body (Mobile-friendly).

---

## 1. LÝ DO ĐỀ XUẤT (BACKGROUND)

- **Đặc thù Mobile App (React Native):**
  Môi trường chạy ứng dụng di động (Android trên thiết bị iMin) không hoạt động như một trình duyệt Web thông thường. Việc lưu trữ và tự động gửi cookie dạng `HttpOnly` hay `Secure` thông qua HTTP client (Axios) trên mobile rất dễ bị mất phiên đăng nhập (session loss), không ổn định khi đóng ứng dụng hoàn toàn hoặc khi hệ điều hành dọn dẹp bộ nhớ.
- **Giải pháp chuẩn ngành di động (Mobile Industry Standard):**
  Lưu trữ cả `AccessToken` và `RefreshToken` trong bộ nhớ an toàn của thiết bị (Secure Storage / MMKV mã hóa) và chủ động truyền nhận thông qua JSON Request/Response Body.

---

## 2. CHI TIẾT THAY ĐỔI YÊU CẦU (API SPECIFICATION CHANGES)

### A. API Đăng Nhập (`POST /v1/device/auth/login`)

- **Request:** (Không đổi)
- **Response:** Trả thêm trường `refreshToken` trực tiếp trong JSON Response Body (thay vì set ở Header cookie).

```json
{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "eyJyZWZyZXNo...", // <--- YÊU CẦU BỔ SUNG TRONG BODY
  "employee": {
    "id": "019e...",
    "email": "cashier1@skystore.com",
    "employeeCode": "NV001",
    "displayName": "Nguyễn Văn A"
  },
  "device": {
    "id": "019e...",
    "deviceCode": "POS-001",
    "name": "Quầy 1"
  }
}
```

---

### B. API Làm Mới Token (`POST /v1/device/auth/refresh`)

- **Yêu cầu truyền lên:** Nhận `refreshToken` trực tiếp từ JSON Body thay vì đọc từ Cookie.
- **Response:** Trả về `accessToken` mới (và tùy chọn `refreshToken` mới nếu xoay vòng token - token rotation).

- **Yêu cầu Request Body:**

```json
{
  "refreshToken": "eyJyZWZyZXNo..." // <--- YÊU CẦU TRUYỀN TRONG BODY
}
```

- **Response Body thành công (200 OK):**

```json
{
  "accessToken": "eyJhbGciOi...",
  "refreshToken": "eyJyZWZyZXNo..." // (Tùy chọn: trả lại refresh token mới)
}
```

---

### C. API Đăng Xuất (`POST /v1/device/auth/logout`)

- **Yêu cầu truyền lên:** Chủ động truyền `refreshToken` trong JSON Body để hủy phiên đăng ký ở Server (hủy hiệu lực token).

- **Yêu cầu Request Body:**

```json
{
  "refreshToken": "eyJyZWZyZXNo..." // <--- YÊU CẦU TRUYỀN TRONG BODY ĐỂ THU HỒI
}
```

- **Response Body thành công (200 OK):**

```json
{
  "success": true
}
```

---

## 3. LỢI ÍCH ĐẠT ĐƯỢC

1. **Hoạt động ổn định 100%:** Tránh hoàn toàn lỗi mất cookie hoặc hết hạn cookie không mong muốn trên môi trường Android di động.
2. **Quản lý linh hoạt:** Phía Client có thể chủ động kiểm tra thời gian hết hạn của `refreshToken` để thực hiện auto-login hoặc ép buộc đăng nhập lại trước khi phát lệnh gọi API.
3. **Bảo mật tuyệt đối:** Token được lưu trong phân vùng Sandbox mã hóa của ứng dụng, an toàn tương đương hoặc hơn Cookie trên các nền tảng di động.
